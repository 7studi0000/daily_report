### 1. わかったこと (核心的な理解)

🔸 **Networkパネルによる通信の可視化とボトルネック特定**

* **読み込み順序の把握:** HTML（Document）→ CSS / JavaScript → XHR（非同期通信）→ 画像・フォント・動画、というリソース取得の流れをウォーターフォールで確認できる仕組みを理解。Document が最初に読み込まれないと後続リソースは始まらない、という依存関係も体感した。
* **Timing による遅延原因の切り分け:** 1リクエストごとに Connection Start（接続準備）→ Request Sent → Waiting（サーバー応答待ち / TTFB）→ Content Download（データ受信）と分解され、緑（Waiting）が長ければサーバー側、青（Download）が長ければファイル容量または回線速度が原因と判断できる分析手法を習得。
* **XHR フィルタと API レスポンスの検証:** ページ表示後に非同期で取得される JSON データ（XHR）だけを絞り込み、Preview タブでオブジェクトツリーとして確認できる。気象庁 P2P ミラーなど外部 API のレスポンス構造を、Console を開かずに Network 上だけで検証できることを確認した。
* **Copy property path による JSON パス取得:** ネストした JSON から必要な値のパスを右クリック一発（`Copy property path`）で取得し、フロントエンドへのデータ流し込みに使える小技を Network パネルでも実践。前回 Console で学んだ手法が API デバッグでも通用することを再確認した。

🔸 **Securityパネルによる HTTPS / 混合コンテンツの検査**

* **公開前チェックの重要性:** ページ全体が HTTPS で保護されているかをグリーン表示で一目確認できる。HTTP アクセスや混合コンテンツ（HTTPS ページ内で HTTP の外部リソースを読み込んでいるケース）が赤や警告で検出される仕組みを理解した。
* **外部 CDN 読み込みの落とし穴:** 自サイトは HTTPS でも、jQuery 等の外部スクリプトが HTTP URL だと Security パネルに警告が出る。CDN 利用時は HTTPS 指定を徹底する必要があることを、気象庁サイトの jQuery 自前ホスティング事例（速度 vs 可用性のトレードオフ）と合わせて理解した。

🔸 **CDN vs 自社サーバの設計判断**

* **可用性と速度のトレードオフ:** 外部 CDN（Google jQuery CDN 等）は高速だが、CDN 障害時にサイト全体が機能不全になるリスクがある。自社サーバーにリソースを置くことで保守運用の一元管理と可用性を優先する判断も、Network パネルで jQuery の読み込み時間を比較しながら理解した。
