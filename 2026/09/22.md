### 1. わかったこと (核心的な理解)

🔸 **コンテンツ幅はヘッダーも本文も同じ箱**

* **960px と左右 4%:** 初級課題のレジュメは、中身の最大幅を 960px、左右の余白を 4% にする契約。メインビジュアルだけ全幅・高さ 600px で、自己紹介は丸切り抜きの横並び、プロフィール画像は両端ぞろえ、600px 以下で縦積み、という役割分担を先に置いてから組んだ。
* **ヘッダーを後から同じ箱へ戻した:** 公式スクショに寄せる途中で、ロゴを画面左端・ナビを右端に出していた。レビューで「ヘッダーの中身も 960px、横パディング 4%」と指定され、本文の「自己紹介」と同じ左端に揃えた。見た目の端と、仕様が決めた箱は別だと分かった。
* **寄せ方は幅とセット:** 「中央寄せ」に見えても、本文は幅を抑えた左寄せだった。スマホのナビは `flex` の等分でリンク幅を揃え、見出しの下線は文字幅だけにすると、スクショの印象と一致した。

🔸 **模写は境界の数値で合わせる**

* **レジュメの合格ライン:** Google HTML/CSS Style Guide に沿って書き、デスクトップと 600px 以下をブラウザで確認してから PR と GitHub Pages にした。提出先は [PR #2](https://github.com/7studi0000/hc_practice/pull/2) と [レジュメ](https://7studi0000.github.io/hc_practice/html_css_output_beginner/)。
* **Zenn はカラムの役割:** エディタガイドの模写では、PC でカード幅・本文幅・右の目次幅を公式の位置に合わせた。見出しの大きさ（タイトル 33px、大見出し 27.2px、小見出し 24px）まで測ってから CSS を直した。公開先は [Zenn模写](https://7studi0000.github.io/hc_practice/zenn_editor_guide/)。
* **ブレイクポイントを早く切ると PC がスマホになる:** 幅 1120px 以下で著者バー・見出し縮小・更新日の非表示が当たっていた。公式は 992px まで PC のまま。1280px と 1100px では著者バーと「目次」ボタンを出さず、更新日と右の目次を残す、という切り分けに直した。

🔸 **公開したあとの見た目は、手元の CSS と一致しないことがある**

* **キャッシュ:** 直したあとも古い CSS のまま見えることがあった。スーパーリロードで読み直すと、ファイル側の指定が画面に出る。9/18 に Network で見た「どのリソースが届いているか」が、模写の確認手順としても使える。

### 2. 次やること (自力で発見する課題)

* **スマホのいいね欄:** 幅 390px で、いいね欄が「1. Webエディター」の見出しにかぶる。公式では見出しが欄の上に全部見えているので、その重なりを直す。
* **まだ揃っていない細部:** 目次の行間、ショートカットの開閉、フッターの並びを、PC とスマホの両方で公式と突き合わせる。
* **次の模写の先に幅を書く:** 実装の前に、コンテンツ幅・余白・PC が崩れる幅を1行で書いてから HTML に入る。

### 3. 感想 (内省)

DevTools で通信を読む段階から、自分で幅を決めて公開する段階に移った数日でした。レジュメで「ヘッダーも 960px」と戻されたことと、Zenn で「1120px だとまだスマホ」と気づいたことは、どちらも同じ失敗です。スクショの印象で寄せると、契約している幅と境界がずれます。数値を先に置いて、公開後は届いている CSS を確認する、という順にすると模写が安定しました。
